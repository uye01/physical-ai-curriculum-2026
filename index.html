운영 원칙

  • 깊이보다 흐름. 한 세션(1시간, 발표 40분 + 토론 15~20분)에 같은 문제를 공유하는 논문 2~3편을 하나의 비교 질문으로 묶는다. 시스템 명세는 anchor 논문 1편만 완전하게 작성한다.
  • 최신 우선. core 계보가 아니면 2025–2026년 논문을 우선한다. 오래된 원리 논문은 발췌·배경 노트로 강등한다.
  • 문제 먼저, 도구는 필요할 때. RT 계보로 한계를 확인한 뒤에 Diffusion·Flow Matching을 배운다. 하드웨어는 논문이 등장하는 Chapter에서 필요한 만큼만.
  • 고전 원전은 발췌로. World Models(2018)와 LeCun position paper(2022)는 독립 세션 없이 계보의 출발점으로만 다룬다.
  • 회사가 아니라 문제로 Chapter를 나눈다. 연구그룹은 비교 태그로만 유지한다.
  • Core / Extension / Update 구분. 새 논문이 나왔다는 이유만으로 Core를 늘리지 않는다 — 새로운 문제 정의·아키텍처·데이터·평가 방식이 있을 때만 승격을 검토한다.
  • 모든 발제의 세 질문. 이전 접근은 무엇에서 막혔는가 → 무엇을 바꿨는가 → 그 변경이 새로 만든 한계는 무엇인가.

CH.01

온보딩과 좌표계

1 session

제품명과 논문 목록을 외우기 전에 전체 질문, 핵심 용어, 스터디 진행 방식을 이해한다.

C01-S01Physical AI 온보딩 — 연구 지형, 용어, 논문 읽는 법Core

Physical AI는 기존 vision-language AI와 무엇이 다르며, 이 분야의 논문·테크리포트를 어떤 기준으로 읽어야 하는가?

  • perception → representation → prediction → planning → action의 연결과 closed loop
  • 최소 로봇 리터러시: observation/state/action, joint·EE space, open/closed-loop, action chunk, teleoperation, control frequency, inference latency
  • 읽는 기준: method / data / system / product claim 구분, claim-evidence 구분, task 정의가 다른 성공률을 직접 비교하지 않기
  • (마지막 5~10분) 하드웨어 지형은 "이런 제품들이 있다" 수준으로만

산출물 — Physical AI problem map 초안 · 공통 발제 템플릿 확정 · 용어집 v1. 서베이 3종(부록 A.1)은 정독하지 않고 좌표 확인용으로 반복 참조한다.

CH.02

VLA 초기 계보 — discrete token과 action chunk

3 sessions

생성모델 이론에 들어가기 전에 VLA의 입력·출력·학습 방식, discrete action token과 action chunk의 장단점을 초기 논문 계보로 체감한다.

C02-S01RT-1 + RT-2 — action token의 탄생과 웹 지식 전이Core

로봇 action을 언어처럼 token으로 예측하면 무엇이 좋아지고, 웹 규모 VLM의 지식은 어디까지 제어로 전이되는가?

  • RT-1: Robotics Transformer for Real-World Control at Scale (2022)anchor
  • RT-2: VLA Models Transfer Web Knowledge to Robotic Control (2023)
  • action discretization과 autoregressive prediction, 13만 episode 데이터 엔진 (RT-1)
  • VLM co-fine-tuning, web knowledge transfer, emergent capability 평가 (RT-2)
  • 두 논문 사이에서 유지된 것(action 표현)과 바뀐 것(백본·데이터·주장)

토론 — token probability는 continuous multimodality의 해결인가, 우회인가? generalization claim과 평가 설계의 간격. 산업계 claim-evidence 표 첫 적용.

C02-S02Open X-Embodiment + OpenVLA — 데이터와 가중치의 공개Core

cross-embodiment 데이터셋과 공개 학습 파이프라인은 왜 그 자체로 연구 기여인가?

  • Open X-Embodiment: Robotic Learning Datasets and RT-X Models (2023)
  • OpenVLA: An Open-Source Vision-Language-Action Model (2024)anchor
  • 서로 다른 로봇 데이터를 합칠 때의 action space·카메라·주파수 정렬, positive transfer의 조건 (RT-X)
  • RT 계보의 공개 구현과 fine-tuning, discrete token의 정밀도·주파수·deployment 비용

산출물 — 공개성·하드웨어 요구량·수정 가능 지점을 담은 재현 가능성 카드. 우리 연구실이 fine-tuning·probing·adapter 연구를 시작할 수 있는 지점은 어디인가?

C02-S03ACT + Mobile ALOHA — action chunking의 초기 계보Core

한 스텝씩 action을 예측하면 왜 실패하며, chunk는 무엇을 해결하고 무엇을 잃는가?

  • Learning Fine-Grained Bimanual Manipulation with Low-Cost Hardware (ACT/ALOHA) (2023)anchor
  • Mobile ALOHA: Bimanual Mobile Manipulation with Whole-Body Teleoperation (2024)
  • compounding error, action chunking과 temporal aggregation, chunk 길이 vs 반응성 trade-off
  • 저가 bimanual teleop rig의 연구적 의미, 베이스 포함 whole-body action과 co-training 효과

연결 — DP·π0·GR00T·RDP의 공통 action 단위. 전신 teleop 데이터 수집은 Ch.11에서 humanoid로 확장. 산출물: single-step / chunk / token 1차 비교표.

CH.03

Action 생성 도구 — 필요한 순간에 배우기

3 sessions

Diffusion, Flow Matching, DiT, action tokenizer를 독립 생성모델 강의가 아니라 로봇 action의 multimodality·정밀도·속도·스케일링 문제에 대한 도구로 이해한다.

C03-S01Diffusion Policy + Flow MatchingCore

같은 관측에서 여러 action이 모두 정답일 때 MSE 회귀는 왜 실패하며, iterative sampling의 비용은 어떻게 줄이는가?

  • Diffusion Policy: Visuomotor Policy Learning via Action Diffusion (2023)anchor
  • Flow Matching for Generative Modeling (2023)
  • action multimodality, observation-conditioned denoising, receding-horizon 실행
  • diffusion↔flow의 관계, vector field·ODE 직관, 적은 sampling step이 제어 주파수에 중요한 이유
  • 기초 범위: DDPM forward/reverse 직관까지만 — ELBO 유도·OT 이론 생략

핵심 장면 — 좌·우 회피가 모두 정답인데 평균 action이 장애물 정면을 향하는 사례. 산출물: 추론 step ↔ latency ↔ control frequency 표 시작.

C03-S02DiT + FAST — 아키텍처와 tokenizer라는 별개의 층위Core

학습 목표(diffusion/flow)와 별개로, 아키텍처와 action tokenizer는 각각 무엇을 결정하는가?

  • Scalable Diffusion Models with Transformers (DiT) (2023)anchor
  • FAST: Efficient Action Tokenization for VLA Models (2025)
  • U-Net 대신 Transformer를 쓰는 이유, conditioning 주입, 스케일링 (DiT)
  • naive binning token이 고주파·정밀 action에서 무너지는 이유, DCT 기반 압축 tokenization (FAST)

토론 — tokenizer가 충분히 좋아지면 discrete vs continuous 논쟁의 결론이 바뀌는가? 연결: RDT·GR00T의 DiT 계열, π0-FAST.

C03-S033D Diffusion Policy + iDP3Core

action model을 그대로 두고 입력 표현만 2D→3D로 바꾸면 왜 데이터 효율이 달라지며, humanoid·egocentric·onboard 환경에서는 무엇이 새로 필요한가?

  • 3D Diffusion Policy (2024)anchor
  • Generalizable Humanoid Manipulation with 3D Diffusion Policies (iDP3) (2024)
  • point cloud 표현, viewpoint invariance, demonstration efficiency
  • egocentric 관측, noisy human data, onboard compute, scene generalization

반증 조건 — depth sensor·calibration 비용까지 포함해도 3D 이득이 유지되는가? Update 지침: 2025-26 후속 3D 정책 연구가 있으면 비교 슬롯 추가.

CH.04

Continuous-action VLA 아키텍처

3 sessions

VLM의 semantic representation과 continuous robot action 사이를 연결하는 구조적 선택을 비교한다.

C04-S01CogACT + Octo — diffusion head를 붙이는 두 가지 동기Core

cognition-action 분리와 재사용성·adaptation이라는 서로 다른 설계 동기는 구조를 어떻게 다르게 만드는가?

  • CogACT: Synergizing Cognition and Action (2024)anchor
  • Octo: An Open-Source Generalist Robot Policy (2024)
  • VLM backbone + diffusion action module 분리, stage-wise training (CogACT)
  • transformer policy, diffusion head, task token, fine-tuning interface (Octo)

토론 — 모듈 분리는 inductive bias인가, scale 부족을 보완하는 engineering choice인가? 새 sensor·robot에 붙일 때 최소 수정 모듈은?

C04-S02RDT-1B + Diffusion-VLA — DiT 스케일업과 reasoning 조건화Core

DiT 기반 action model을 대규모 bimanual foundation model로 키우면 무엇이 달라지고, reasoning을 조건으로 넣으면 무엇을 얻고 잃는가?

  • RDT-1B: a Diffusion Foundation Model for Bimanual Manipulation (2024)anchor
  • Diffusion-VLA (2024)
  • diffusion transformer, heterogeneous bimanual data, unified action representation
  • self-generated reasoning 조건화와 interpretability claim

토론 — 통합 action space는 cross-embodiment의 해결인가, 공통 좌표계로 미룬 것인가? π0와의 차이: diffusion vs flow, 공개 vs 폐쇄. Update 지침: 2025-26 후속 버전 확인.

C04-S03경량·공개 VLA의 흐름 — OpenVLA-OFT + SmolVLAExtensionUpdate

빅테크 밖의 공개 VLA는 어떤 구조적 차별화로 경쟁하는가?

  • Fine-Tuning VLA Models: Optimizing Speed and Success (OpenVLA-OFT) (2025)
  • SmolVLA: Affordable and Efficient Robotics (2025)
  • parallel decoding, continuous action head, fine-tuning 레시피 (OFT)
  • 경량 VLM + flow expert + community data + async inference (SmolVLA)
  • Landscape: WALL-OSS, AgiBot GO-1, GR-3, RoboVLM 등은 설계가 다를 때만 짧게

개인 연구자 관점 — 연구실 GPU에서 fine-tuning 가능한 모델은 무엇이며, 무엇을 포기한 설계인가?

CH.05

4 sessions

C05-S01π0 + π0.5 — flow expert와 open-world 일반화Core

discrete token의 정밀도·속도 한계를 flow-matching action expert가 어떻게 공격하며, dexterity가 확보된 뒤에도 처음 보는 환경·long-horizon task에서 실패하는 이유는 무엇인가?

  • π0: A Vision-Language-Action Flow Model for General Robot Control (2024)anchor
  • π0.5: a VLA with Open-World Generalization (2025)
  • VLM backbone + flow expert + action chunk, heterogeneous robot data (π0)
  • heterogeneous co-training, web data, semantic subtask, open-world task 정의 (π0.5)
  • 성능 숫자보다 '새 집에서 부엌 정리'라는 평가 task 정의 방식을 본다

토론 — semantic hierarchy가 control generalization을 만든 것인가, task decomposition을 외부에서 제공한 것인가?

C05-S02π*0.6 / RECAP + Real-Time Chunking — 경험 학습과 실시간 실행Core

demonstration만으로 학습한 VLA가 실제 실패에서 배우려면, 그리고 큰 flow policy가 추론 지연 속에서도 끊기지 않고 움직이려면 각각 무엇이 필요한가?

  • π*0.6: a VLA That Learns From Experience (RECAP) (2025)anchor
  • Real-Time Execution of Action Chunking Flow Policies (2025)
  • experience collection, intervention, advantage-conditioned policy, reward/judge (RECAP)
  • 추론 지연 동안 chunk를 이어붙이는 inpainting식 비동기 실행 (RTC)

쟁점 — 보상은 누가 정의하며 VLM-as-judge를 얼마나 신뢰할 수 있는가? chunk를 어느 구간에서 잘라도 안전한가? 연결: Ch.13 평가, Ch.10 실시간성.

C05-S03Hi Robot + Knowledge Insulation — 계층과 학습 레시피Extension

낮은 수준 policy 위에 System 2 VLM을 얹는 계층화와, VLM 지식을 보호하며 action expert를 학습시키는 레시피는 각각 어떤 실패를 막는가?

  • Hi Robot: Open-Ended Instruction Following with Hierarchical VLAs (2025)
  • Knowledge Insulating Vision-Language-Action Models (2025)
  • open-ended instruction, 사용자 개입·피드백 처리, 고수준-저수준 분업 (Hi Robot)
  • continuous action head의 gradient가 VLM representation을 훼손하는 문제와 차단 레시피 (KI)

발표 템플릿과 규칙

  • 한 문장 위치. "이 연구는 ___ 계보에서 ___ 문제를 해결하기 위해 ___를 바꾼 연구다." 여러 논문 세션은 "이 세션은 ___라는 질문에 대해 ___와 ___를 비교한다"를 추가.
  • 시스템 명세. robot/embodiment, sensor, observation, action space, action chunk, control frequency, model size, data source, task·성공 정의, 공개 여부 — anchor 논문만 완전하게, 나머지는 달라진 항목만.
  • 가장 강한 증거와 가장 약한 증거. 주장을 가장 잘 지지하는 실험 1개, 부족한 실험 또는 누락된 대조군 1개.
  • 재현·연구 가능성. 공개 자원으로 재현 가능한 부분 / 우리 연구실에서 수정 가능한 부분 / 빅테크 자원 없이는 어려운 부분.
  • 최신성 규칙. core 계보가 아니면 2025-26 논문 우선. 발표 1주 전 arXiv 최신 버전·공식 페이지·코드 확인. 단순 SOTA 향상은 10분 업데이트로. 블로그만 있고 방법·평가가 없으면 Core 지정 금지. 논문 버전·확인 날짜를 슬라이드에 기록.

최종 체크리스트 — 스터디 종료 시 답할 수 있어야 하는 것

  • VLA 논문을 discrete/compressed token, diffusion head, flow head로 분류할 수 있다.
  • action chunk 길이와 replanning frequency의 trade-off를 설명할 수 있다.
  • Flow Matching(학습 목표), DiT(아키텍처), FAST(tokenizer)가 서로 다른 층위임을 설명할 수 있다.
  • π0 → π0.5 → π*0.6의 발전을 '한계 시인 사슬'로 설명할 수 있다.
  • pixel generation, latent prediction, explicit geometry의 전제를 비교할 수 있다.
  • world model을 representation, simulator, data engine, reward/evaluator로 분해할 수 있다.
  • reasoning trace의 매체와 latency·interpretability trade-off를 분석할 수 있다.
  • manipulation VLA와 locomotion RL의 문제 설정 차이를 설명할 수 있다.
  • 촉각·힘 신호를 센서·주파수·융합 위치 기준으로 비교할 수 있다.
  • success rate를 hardware·task·control 조건 없이 직접 비교하지 않는다.
  • 2025-2026년 논문 지형에서 다음에 검증해 볼 만한 연구 방향을 최소 하나 말할 수 있다.
